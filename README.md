# KBS website

A scroll driven site for KB HOUSE, with an admin only dashboard behind it.

Next.js (App Router) · TailwindCSS · TypeScript · Supabase · Cloudinary · Vercel.

---

## Run it

You should have two things from the handoff, sitting side by side:

```
kbs 3d\
  kbs-web-source.zip      the project
  media\                  the video encodes and the stills
```

Unzip `kbs-web-source.zip` in place, so `package.json` ends up next to the `media`
folder. Then, in that folder:

```
setup-media.bat        Windows. On macOS or Linux: ./setup-media.sh
npm install
npm run dev
```

Open **http://localhost:3000**. It redirects to `/bn` or `/en` depending on your
browser's language; both are always reachable directly.

`setup-media.bat` copies the two video files and unpacks the stills into
`public\media`, where the app looks for them. The videos are too large to travel
inside the source zip, which is why they arrive alongside it. The script prints how
many files it placed; it should say 20.

**It runs with an empty `.env.local`.** With no Supabase and no Cloudinary the site
uses the content built into `src/content/seed.ts` and serves media from
`public/media`. Nothing is broken in that state. That is deliberate: content and
media must never be able to take the page down.

If port 3000 is busy, `npm run dev -- -p 3001` and use that port instead.

## Connect Supabase

1. Create a project at supabase.com.
2. Open the SQL editor and run the whole of `supabase/schema.sql`.
3. Copy the project URL and both keys from Project settings › API into `.env.local`.
4. Create your admin user under Authentication › Users › Add user. Use a real email
   and a strong password, and tick "auto confirm".
5. Back in the SQL editor, add that user to the allow list:

   ```sql
   insert into public.admins (user_id, email)
   select id, email from auth.users where email = 'you@example.com';
   ```

   Being in Auth is not enough on its own. The dashboard checks for a row in
   `admins` as well, so an account created by accident cannot get in.

6. Sign in at `/en/admin/login`.

There is no public sign up anywhere in the app. Accounts are created by hand.

## Connect Cloudinary

Upload everything in `public/media` to a folder called `kbs` in your Cloudinary
account, keeping the file names exactly as they are, then set
`NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` in `.env.local`. The site switches over on the
next build.

**Do not let Cloudinary re-encode `hero-scrub.mp4` or `hero-scrub.webm`.** They were
encoded with a keyframe every 8 frames, which is the only reason the scroll scrub is
smooth rather than stuttery, and a transformation would throw that away. They are
requested untransformed on purpose.

## Deploy to Vercel

1. Push to GitHub.
2. Import the repo in Vercel.
3. Add every variable from `.env.example` under Settings › Environment Variables.
   `SUPABASE_SERVICE_ROLE_KEY` must be server only, never prefixed `NEXT_PUBLIC_`.
4. Deploy.

The social preview tags, the sitemap and robots.txt resolve their own absolute URLs
from `NEXT_PUBLIC_SITE_URL`, falling back to Vercel's own production URL, so there is
no file to edit by hand after the first deploy. Set `NEXT_PUBLIC_SITE_URL` once you
point a real domain at it.

## How content works

`seed.ts` is what ships. The dashboard writes overrides into the `site_content`
table and those are merged over the seed at render time, key by key. So:

- Anything the client never edits keeps the seed value.
- Anything they do edit wins, immediately, with no deploy.
- If Supabase is unreachable, the seed renders and the site still works.

The Text tab in the dashboard is generated by walking the seed for every bilingual
string, so any copy added to `seed.ts` becomes editable automatically. There is no
list of form fields to keep in sync.

## Things that will bite you if you change them

**The static hero gate** appears twice, once in `globals.css` and once as the
`GATES` array in `ScrubHero.tsx`. They must match character for character. If they
drift, one side hides the scrub while the other still loads the video. The scrub
now runs on every viewport, phones and tablets included; only
`prefers-reduced-motion: reduce` still falls back to the static composition.

**`VIDEO_ENDS_AT` in `ScrubHero.tsx`** is why the page settles exactly when the
footage reaches its resting frame. The video finishes at 88 percent of the hero
scroll and holds there, which turns the last stretch into a real settle plateau. Set
it to 1 and the closing headline and the call to action arrive over a camera that is
still moving.

**The band scrim alphas** in `seed.ts` were tuned against each band's own worst
frame, measured on the composited page, not guessed. Every band clears 3.5:1 with
margin, the lowest being the settle at 4.0. If you brighten them, re-measure. The
bright sky and white concrete are the hardest background there is for light text.

**Bengali never splits to characters.** `SplitText.tsx` detects Bengali and animates
at word level, because splitting a connected script into per character spans breaks
its conjuncts and vowel marks.

**Two video encodes ship on purpose.** H.264 is primary; VP9 is the fallback for
browsers built without the proprietary codec, where an H.264 blob fails outright
after downloading in full. The choice is made with `canPlayType` before any bytes
move.

## The public site never shows approval status

RAJUK status is stored in the `internal_notes` table, which has its own access rules
and is not readable by the public role. It is edited on the Internal tab of the
dashboard and is not rendered anywhere on the site. It was kept out of
`site_content` specifically so it cannot end up on a page by accident.
